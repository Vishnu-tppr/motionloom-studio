# Product motion

Start from the real user problem and one product promise. Build the sequence: hook → problem signal → product entrance → one clear interaction → visible result → brand payoff. Use real supplied screenshots/recordings when accuracy matters; procedural UI should be explicitly illustrative.

## SaaS/ad playbook (from broadcast + SaaS-launch research)

- **Hook first (0–3s):** one promise or provocation on screen before any logo. Punch-slam the hook (`punchSlam` in `typography.js`), hold it, then move. Test 2–3 hook variants (stat, question, before/after) and pick against written criteria.
- **One interaction per shot:** cursor with intent → click ripple (`cursorRipple`) → request/processing (`counter`, `barChart`/`lineChart` progress) → visible result. Pause around meaningful state changes so viewers can read the UI.
- **Keep UI legible:** large crop, stable focal region, short labels (≤6 words per card), minimum 18px type at 720p, high-contrast accent as the recurring token (e.g. amber trace line).
- **Kinetic type restraint:** one type voice per film (kinetic title for hooks, typewriter for code/logs, word-stagger for benefits). Never animate body copy character-by-character for readability.
- **Pacing:** cut on beats (~0.5–1.5s per idea in ads; ~2s per shot in explainers). No dead air; hold the payoff longer than setup details.
- **Sound plan (placeholders, not synthesis):** storyboard columns must list music bed + SFX cues per shot even though v0.1 exports silent MP4 — whoosh on wipes, click on interaction, riser into payoff, resolve on end card. This is the contract a later audio milestone will fill.
- **Truthfulness:** visual truth beats style. Do not invent product behavior or fake interface states. Redact secrets/PII. Record asset permissions; do not imply unsupported features.

## Proof order

Storyboard → one look still (`out/look.png`) → 2–3 hook variants → contact sheet + transition strips → full export. Never claim the ad works from source inspection alone.
